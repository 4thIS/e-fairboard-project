# 시스템 아키텍처

## 1. 개요
E-FairBoard는 종이 포스터/팜플렛을 e-Paper로 대체하고, 여러 게시판을 중앙에서 한 번에
업데이트하는 저전력 무선 안내 시스템이다. 관리자는 웹 대시보드에서 콘텐츠를 작성·예약하고,
LoRa 게이트웨이가 각 노드에 변경분만 전송한다. 노드는 e-Paper로 표시하고 갱신 성공/배터리
상태를 보고한다.

## 2. 토폴로지
```
[Vue 대시보드] ─HTTP─ [FastAPI 서버(노트북)] ─USB Serial─ [ESP32 게이트웨이 +Core1262]
                                                                   │ LoRa 920MHz
                       ┌───────────────────────────┬───────────────┘
                 [노드1 ESP32+Core1262+ePaper] [노드2 ESP32+Core1262+ePaper]
                  배터리/딥슬립, QR 온디바이스 렌더, ACK 보고
```
- NodeID: `0x00`=게이트웨이, `0x01~0xFE`=노드, `0xFF`=브로드캐스트
- 게이트웨이가 마스터, 노드는 요청에 응답.

## 3. 구성요소
### 3.1 중앙 관리 서버 (server/)
- 관리자 웹 대시보드(Vue 3), 게시물 작성/수정/삭제/예약
- 노드별·그룹별 콘텐츠 배포, 템플릿 선택, QR URL 관리
- 종이 절감량·업데이트 성공률·노드 배터리 시각화
- 게이트웨이와 USB 시리얼 브리지(pyserial)

### 3.2 LoRa 게이트웨이 (gateway/)
- ESP32 + Core1262(SX1262)
- 서버↔LoRa 변환, 노드 주소 관리, 재전송, ACK 수집
- 서버 연결은 USB 시리얼(MVP)

### 3.3 e-Paper 노드 (node/)
- ESP32 + Core1262 + e-Paper 2.9"
- 콘텐츠 수신·CRC 검증·로컬 저장(LittleFS)·화면 갱신·배터리 보고
- 평상시 딥슬립, QR은 노드가 직접 렌더

## 4. 기술 스택
| 영역 | 선택 |
|------|------|
| 펌웨어 빌드 | PlatformIO + ESP32 Arduino core |
| LoRa | RadioLib (SX1262 / Core1262 SPI) |
| e-Paper | GxEPD2 + Adafruit_GFX (부분갱신) |
| QR | ricmoo/QRCode (온디바이스 렌더) |
| 저전력/저장 | esp_deep_sleep + LittleFS |
| 서버 | FastAPI + APScheduler + SQLite + pyserial |
| 프론트 | Vue 3 + Vite + Pinia |

## 5. 역할 분담
| 담당 | 브랜치 | 영역 |
|------|------|------|
| 우진(팀장) | `wj` | 시스템 통합 + 게이트웨이 펌웨어 + 패킷 프로토콜 |
| 준표 | `jp` | 서버·대시보드(FastAPI+Vue) + 시리얼 브리지 + DB·예약 |
| 효민 | `hm` | 노드 펌웨어 — e-Paper 렌더 + QR + 딥슬립 + 배터리 |

## 6. MVP 범위
텍스트 + QR / 2노드 / 일괄·개별 배포 / ACK·재전송 / 배터리 보고.
이미지 분할 전송, Wi-Fi 게이트웨이는 스트레치.

## 7. 정량 목표
- 2개 노드 동시 제어(일괄·개별)
- LoRa 통신 성공률 95% 이상
- 텍스트/QR 공지 업데이트 30초 이내
- 노드 1회 충전 2주 이상(저전력 보드 기준)
- 종이 팜플렛 100장 이상 대체 시나리오
