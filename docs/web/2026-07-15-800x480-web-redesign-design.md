# 7.5" 800×480 전환 — 웹 파트 재설계 (흑백 1차) (v1.0)

> 2026-07-15 · 담당: 우진(`wj`) · 대상: `server/backend/app/protocol/templates.py`, `tools/gen_templates.py`, `server/frontend/`
> 선행: [PROTOCOL.md](../PROTOCOL.md) v0.2, [ARCHITECTURE.md](../ARCHITECTURE.md), [2026-07-15-portrait-layout-design.md](2026-07-15-portrait-layout-design.md)
> 하드웨어가 2.9"(296×128 흑백)에서 **7.5"(800×480 3색)**로 확정됐다. 웹의 캔버스·템플릿 좌표·폰트·미리보기를 여기에 맞춘다.

## 1. 목적·범위

패널 교체로 낡아버린 웹 파트를 800×480에 맞춘다. **흑백 우선** — 적색(3색)은 프로토콜 색 필드가
필요해(준표 협의) 다음 설계(v0.3)로 미룬다.

범위: 캔버스 값 변경, 템플릿 5종 좌표 재배치, 폰트 크기 상향, 미리보기 배율 재설계.
범위 밖: 적색 지원, "30초 목표" 재조정(PROTOCOL.md §9, 팀 결정), transport 계층(SerialTransport).

## 2. 확정 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 색 | **흑백 먼저, 적색은 v0.3** | 적색은 SET_FIELD 색 필드 필요 → 준표 프로토콜 협의 |
| 재배치 방식 | **비례 확대** — 같은 필드 구조, 큰 폰트 | 브레인스토밍 목업에서 선택. 안전·빠름, 먼 거리 가독성 |
| 폰트 (A안) | 제목/헤더 **48px**, 본문 **32px**, 부스 강조 **64px** | 목업 비교에서 선택. 16×16 정수배라 새 폰트 불필요 |
| 미리보기 배율 | **컨테이너 맞춤 축소**(분수 배율 허용) | 800×480은 ×1도 커서 카드 2장이 안 들어감. 정수배율 원칙은 296 시절 제약 |
| 잘림 판정 | **실제 800px 기준으로 계산**, 표시만 축소 | 미리보기가 거짓말하지 않는다는 원칙 유지 |

## 3. 캔버스 — 이미 뚫려 있는 배관

`TemplateDef`는 이미 `canvas_w`/`canvas_h`를 갖고(커밋 1b92c79), `field_avail_w`가 전역이 아니라
템플릿 캔버스를 쓴다. **그래서 이번 작업은 캔버스 값과 좌표만 바꾸면 된다** — 잘림 계산은 자동으로 맞는다.

- 가로 템플릿(0~3): `canvas_w=800, canvas_h=480` (기본값을 800×480으로 변경).
- 세로 템플릿(4 팀 소개): `canvas_w=480, canvas_h=800` (패널을 세움).

`TemplateDef`의 기본값을 296×128 → **800×480**으로 바꾼다. (세로 템플릿은 지금도 명시적으로 덮어쓰므로,
480×800으로 값만 갱신.)

## 4. 폰트 — 16×16 정수배 (새 폰트 불필요)

`scale_for(font_px) = font_px // 16`이 이미 정수배를 지원한다. 48=×3, 64=×4가 그대로 나온다.

- 검증 테스트 `test_font_size_is_16_or_32`를 **`font_size % 16 == 0`으로 완화**한다(16/32/48/64 허용).
- 16×16을 ×3·×4로 키우면 픽셀이 도드라지는 레트로 질감 — 7.5" 전자종이에 어울림. 더 매끄러운 큰 글자를
  원하면 큰 원본 폰트를 새로 굽는 선택지가 있으나 펌웨어 작업이 커서 이번 범위 밖(준표).

## 5. 템플릿 5종 좌표 (검산 완료)

규칙: 여백 `x=24`, 제목/헤더 48px, 본문 32px, 부스 강조 64px, QR 160px(가로)·256px(세로).
QR은 우하단(가로)·가운데하단(세로)에 둬서 **어떤 필드 행과도 세로로 겹치지 않는다** → 모든 행 `avail_w`가
캔버스 폭 전체. `max_bytes = (avail_w // font_px) × 3` (한글 3B).

## 6. 프론트엔드 — 미리보기 배율

`EpaperPreview`는 이미 템플릿 `canvas`를 읽는다(커밋 a026b5b). 바꿀 것은 **배율 로직**뿐이다.

- 현재: `previewScale = min(want, canvas.h*2<=320 ? 2 : 1)` — 정수 캡. 800×480에선 항상 ×1이라 여전히 큼.
- **변경: 컨테이너 박스 맞춤 축소.** 미리보기를 담을 박스의 폭·높이를 재서 **둘 다 넘지 않게**
  `scale = min(박스폭 / canvas.w, 박스높이 / canvas.h)` (상한 없이 분수 허용, `image-rendering: pixelated`).
  이렇게 하면 가로(800×480)는 폭이, 세로(480×800)는 높이가 제약이 되어 **한 공식으로 둘 다** 처리된다.
  - 대시보드 카드: 카드가 정한 박스(예: 폭 ~360px × 높이 ~280px)에 맞춰 축소.
  - 편집 다이얼로그: 더 넉넉한 박스 → 더 큰 배율.
  - `ResizeObserver`(또는 부모가 넘기는 박스 크기 prop)로 박스 치수를 얻는다.
- **잘림(`clip`)은 실제 `avail_w`(800px 기준)로 계산** — 표시 배율과 무관. `epaper/text.ts`는 그대로.
- `MAX_PREVIEW_H`·정수 캡 로직 제거. `types.ts`의 `DEFAULT_CANVAS`는 800×480으로 갱신.
- NodeCard: 가로(800×480)·세로(480×800) 카드가 섞이면 높이가 크게 다르다 → 그리드가 높이 차이를
  견디게(`align-items: flex-start`는 이미 적용). 카드 폭은 반응형으로.

## 7. 테스트

- `templates.py`: 좌표 변경은 기존 `test_max_bytes_fits_screen_width`·`test_geometry_inside_each_templates_canvas`가
  자동 검증(캔버스 기준). `test_font_size_is_16_or_32` → `% 16 == 0`으로 완화 + 이름 갱신.
- 드리프트: `tools/gen_templates.py` 재실행 → `node/templates.h` 재생성(좌표·캔버스 반영), `--check` 통과.
  (좌표만 바뀌므로 생성기 코드 변경은 없다. 헤더 재생성만.)
- 프론트 `text.spec.ts`: 잘림 규칙은 캔버스 무관이라 기존 테스트 유지. 배율 로직은 수동 검증.
- 수동: 편집 다이얼로그에서 각 템플릿 선택 → 미리보기가 800×480(세로는 480×800)으로, 컨테이너에 맞게
  축소되어 그려지는지. 필드 초과 입력 시 잘림 경고가 800px 기준으로 뜨는지.
