# 웹 파트 비주얼 디자인 — 관리자 대시보드 (v1.0)

> 2026-07-14 · 담당: 우진(`wj`) · 대상: `server/frontend/` (Vue 3 + Element Plus)
> 짝 문서: [2026-07-08-web-design.md](2026-07-08-web-design.md) — 그쪽이 **구조**(페이지·상태·API), 이쪽이 **외형**(색·타이포·형태)이다.
> 전제: 1순위 관객은 **경진대회 심사위원**. 매일 쓰는 관리자가 아니라 5분 보는 사람이다.

## 1. 컨셉 — 화면이 곧 e-Paper

e-Paper는 그릴 수 있는 게 극단적으로 적다. **그림자도, 그라데이션도, 안티에일리어싱도 없다.**
색은 흑·백, 많아야 적색 한 칸이 전부다(3색 패널 기준). 우리 노드는 그중에서도 **흑백 2색**만 쓴다
(`GxEPD2_290_T94`).

**대시보드가 그 제약을 그대로 따른다.** 색이 3개뿐인 것은 미니멀리즘 취향이 아니라 **제품이 실제로
살고 있는 조건**이다. "왜 이렇게 단순한가"에 대한 답이 하나 있다 — 우리가 제어하는 화면이 이만큼밖에
못 그리기 때문이다.

정직하게 말하면 `--epd-red`는 **대시보드 전용 은유**다. 노드는 빨강을 그리지 않는다(§11).
e-Paper 계열이 가질 수 있는 유일한 유채색을 빌려와 경고에 쓰는 것이고, 이 사실을 숨기지 않는다.

이 컨셉이 아래 모든 결정의 근거다. 규칙을 어기고 싶을 때는 **실물 e-Paper가 그걸 할 수 있는가**를
먼저 물을 것.

## 2. 확정 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 미적 방향 | **전자 종이** — 백지 배경, 먹색 텍스트, 그림자 없음 | 제품과 일관. 조용해야 미리보기가 산다 |
| 색의 역할 | **경고 전용 1색**(e-Paper 적색). 긍정 수치는 색 없이 크기로 | 화면에 빨간 게 보이면 무조건 문제 → 시연 중 시선 유도가 명확 |
| 강조 수단 | **색이 아니라 서체** — 수치·기술값은 픽셀 폰트(Neo둥근모) | 색을 경고에 썼으므로 강조는 타이포가 맡는다 |
| 픽셀 폰트 크기 | **16의 정수배만**(16/32/48/64px) | 16×16 비트맵은 정수배에서만 선명. 노드 `font_size` 규칙과 같은 원인 |
| 첫 화면 주인공 | **노드 2개의 e-Paper 미리보기 대형** | 배포하면 심사위원 눈앞에서 화면이 바뀐다. 하드웨어 없는 게 약점이 아니게 된다 |
| 미리보기 충실도 | 노드와 **픽셀 단위 동일**. 잘라내기 폭은 **서버가 계산해 내려준다** | 미리보기가 거짓말하면 시연의 주인공이 신뢰를 잃는다 (§6) |
| 폰트 배포 | **자체 호스팅**(CDN 금지) | 시연장에 인터넷이 없을 수 있다 |
| 시뮬 패널 | 숨기지 않고 대시보드에서 바로 닿게 | 심사위원 앞에서 일부러 장애를 일으키는 장치 (§9.5) |

## 3. 색

```css
:root {
  --ink:        #1A1A1A;  /* 텍스트·아이콘·기본 모든 것. e-Paper 검정은 순수 검정이 아니다 */
  --paper:      #FFFFFF;  /* 카드·미리보기 바탕 */
  --paper-bg:   #F5F4F0;  /* 페이지 배경 — 살짝 눌러야 흰 미리보기가 도드라진다 */
  --epd-red:    #C8302A;  /* 경고·실패·오프라인·저배터리. e-Paper 적색 잉크 */

  --ink-60:     #6B6B6B;  /* 보조 텍스트 */
  --ink-40:     #8A8A8A;  /* 입력창·버튼 등 **조작 가능한 것의 테두리**. 본문 텍스트 금지 */
  --rule:       #D4D4D0;  /* 장식용 구분선 — 카드 divider, 차트 격자. 테두리에 쓰지 말 것 */
  --fill:       #EEEDE9;  /* 비활성 배경·게이지 트랙 */
}
```

**빨강은 경고에만 쓴다.** 성공·긍정·브랜드에 쓰지 않는다. 이 규칙이 깨지는 순간 색이 의미를 잃는다.

### 대비 (실측)

배경 두 가지(`--paper` #FFFFFF, `--paper-bg` #F5F4F0) 모두에 대해 계산했다.

| 토큰 | vs paper | vs bg | 판정 | 허용 용도 |
|---|---:|---:|---|---|
| `--ink` | 17.40:1 | 15.81:1 | AA 통과 | 전부 |
| `--epd-red` | 5.37:1 | 4.88:1 | AA 통과 | 본문 크기 경고 텍스트 OK |
| `--ink-60` | 5.33:1 | 4.84:1 | AA 통과 | 보조 텍스트 OK |
| `--ink-40` | 3.45:1 | 3.14:1 | 본문 **실패**, UI 경계 통과 | **테두리 전용**, 텍스트 금지 |
| `--rule` | 1.49:1 | 1.35:1 | 둘 다 실패 | **장식선 전용** |

**`--rule`을 조작 가능한 요소의 테두리에 쓰면 안 된다.** 1.49:1은 WCAG 1.4.11(UI 컴포넌트 경계
3:1)에 한참 못 미쳐서, 저시력 사용자가 입력창을 못 찾는다. **입력창·버튼·셀렉트의 테두리는
`--ink-40`(3.45:1)을 쓴다.** `--rule`은 카드 안의 구분선과 차트 격자처럼 없어도 되는 선에만 쓴다.

`#8A8A8A`가 3:1을 넘는 가장 밝은 값이라 새 토큰을 만들지 않고 `--ink-40`의 역할을 나눴다.

**색맹 대응 — 색만으로 상태를 표현하지 않는다.** 경고는 반드시 **형태 + 텍스트**를 동반한다.

| 상태 | 형태 | 색 | 텍스트 |
|---|:---:|---|---|
| 온라인 | `●` (채움) | `--ink` | "온라인" |
| 오프라인 | `○` (빔) | `--epd-red` | "오프라인" |
| 알 수 없음 | `◌` (점선) | `--ink-40` | "확인 중" |
| 배포 성공 | `●` | `--ink` | "성공" |
| 배포 부분 성공 | `◐` (반) | `--ink` | "부분 성공" |
| 배포 실패 | `✕` | `--epd-red` | "실패" |

## 4. 타이포

| 역할 | 폰트 | 크기 |
|------|------|------|
| 본문·라벨·버튼 | **Pretendard** | 13 / 14 / 16 / 20px |
| 수치·강조·기술값·로고 | **Neo둥근모** (픽셀) | **16 / 32 / 48 / 64px만** |
| 코드·패킷 덤프·SEQ | **Neo둥근모 Code** (픽셀 모노) | 16px |
| e-Paper 미리보기 내부 | **Neo둥근모 16px** (§6 규칙 준수) | 16px 고정, 정수배 확대 |

둘 다 SIL OFL 1.1이라 자체 호스팅·재배포에 문제가 없다. Neo둥근모는 노드 펌웨어의
`assets/efb_hangul16.bin`과 **같은 원본 폰트**다 — 미리보기와 대시보드가 같은 글자를 쓴다.

**픽셀 폰트는 16의 정수배에서만 쓴다.** 16.5px 같은 값은 서브픽셀 보간으로 뭉개진다.
`font-smooth: never`, `-webkit-font-smoothing: none` 을 픽셀 폰트에 적용한다.

무엇을 픽셀로 쓰는가 — **기계가 만든 값**(수치·ID·기술값)은 픽셀, **사람이 읽는 문장**은 Pretendard.

```
종이 절감          ← Pretendard 14px, --ink-60
   127장           ← Neo둥근모 48px, --ink        ("장"은 Pretendard 20px)

노드 0x01          ← Neo둥근모 16px  (기계 값)
상태  온라인        ← Pretendard 14px (사람 문장)
RSSI  -62 dBm      ← Neo둥근모 16px  (기계 값)
마지막 응답 3초 전   ← Pretendard 13px, --ink-60
```

## 5. 형태·간격

- **그림자 없음.** `box-shadow: none`을 전역으로. e-Paper에는 그림자가 없다.
- **`border-radius: 0`.** 픽셀 그리드에 맞춘다. 예외 없음.
- **선은 1px `--rule`.** 카드 구분은 테두리로 하지 그림자로 하지 않는다.
- **간격은 8px 그리드**(16의 절반). 4px은 아이콘·배지 내부에서만.
- **전환 효과는 최소.** e-Paper는 갱신이 느리고 뚝뚝 끊긴다. 부드러운 페이드보다 **즉시 전환**이
  제품에 정직하다. 예외는 배포 진행바 — 이건 시간의 흐름을 보여주는 게 목적이므로 애니메이션한다.

## 6. e-Paper 미리보기 — 노드와 픽셀 단위로 같아야 한다

미리보기는 이 시연의 주인공이다. **미리보기가 거짓말하면 시연 전체가 무너진다.**
노드가 실제로 그리는 것과 다른 걸 보여주면 안 된다.

### 6.1 렌더 규칙 (노드 `node_core`와 동일)

| 항목 | 규칙 | 출처 |
|---|---|---|
| 캔버스 | 296 × 128, 흑백 1비트 | `templates.h` `CANVAS_W/H` |
| 확대 | **정수 배율만**(×2 = 592×256). `image-rendering: pixelated` | 픽셀 보간 금지 |
| 폰트 | Neo둥근모, 한글 16px 전각 / ASCII 8px 반각 | `efb_hangul16` |
| 필드 크기 | `font_size`가 16이면 ×1, 32면 ×2 | `scale_for()` |
| 좌표 | `GET /api/templates`의 `x`, `y` | `templates.py` (단일 소스) |
| **잘라내기** | **가용 폭을 넘는 글자는 그리지 않는다** | `draw_utf8()` |
| QR | `qrcode` npm으로 URL에서 생성, `QrDef` 박스에 배치 | 노드도 URL만 받아 직접 렌더 |

### 6.2 가용 폭은 서버가 계산해 내려준다 (백엔드 변경)

QR 박스와 **세로로 겹치는 행**만 가용 폭이 `QR.x - f.x`로 줄어든다. 안 겹치는 행은 캔버스 끝까지 쓴다.

이 규칙은 이미 **두 곳**에 있다 — `node_core/layout.cpp`의 `field_avail_w()`와 서버
`test_max_bytes_fits_screen_width`. 프론트에 또 구현하면 **세 번째 복사본**이 되고,
2026-07-14에 `templates.h`에서 겪은 드리프트를 똑같이 다시 만든다.

**그래서 서버가 계산해서 내려준다.** `GET /api/templates`의 각 필드에 `avail_w`를 추가한다.
프론트는 받아쓰기만 하고 공식을 모른다.

```
GET /api/templates
[{ "id": 0, "name": "행사 안내",
   "fields": [
     { "id": 0, "name": "제목", "x": 8, "y": 8,
       "font_size": 16, "max_bytes": 54, "avail_w": 288 },   ← 추가
     { "id": 1, "name": "일시", "x": 8, "y": 48,
       "font_size": 16, "max_bytes": 39, "avail_w": 216 },   ← QR과 겹쳐서 줄어듦
     ...
   ],
   "qr": { "x": 224, "y": 32, "size": 64 } }]
```

`templates.py`에 `field_avail_w(field, qr)` 함수를 추가하고 `as_dict()`가 결과에 싣는다.
기존 `test_max_bytes_fits_screen_width`가 이미 같은 공식을 검증하므로 그 함수를 재사용하면
테스트가 자동으로 함수를 지킨다.

### 6.3 두 곳에서 재사용

| 위치 | 데이터 소스 |
|---|---|
| 게시물 작성 폼 — 라이브 미리보기 | 입력 중인 폼 값 |
| 대시보드·노드 상세 — 현재 화면 | `GET /nodes/{id}`의 `display_state` |

같은 `<EpaperPreview>` 컴포넌트, props만 다르다.

### 6.4 입력 초과를 미리 보여준다

`max_bytes`는 **한글 기준**이라 ASCII가 섞이면 바이트는 남는데 픽셀은 넘칠 수 있다
(ASCII는 바이트당 8px, 한글은 5.33px). 노드는 넘치는 글자를 잘라내지만, **관리자는 잘린다는 걸
배포 전에 알아야 한다.**

미리보기가 잘라내는 순간 해당 필드 입력창에 경고를 띄운다 — "화면에서 잘립니다" + `--epd-red`.
서버 검증(`max_bytes`)과 별개의 **픽셀 폭 경고**다.

## 7. Element Plus 오버라이드

색을 **더하는 게 아니라 빼는 방향**이라 오버라이드가 짧다. CSS 변수로 대부분 끝난다.

```css
:root {
  --el-color-primary: var(--ink);        /* 기본 버튼이 검정 */
  --el-color-danger:  var(--epd-red);
  --el-color-success: var(--ink);        /* 성공은 색이 아니라 형태로 */
  --el-color-warning: var(--epd-red);
  --el-border-radius-base:  0;
  --el-border-radius-small: 0;
  --el-border-color: var(--ink-40);        /* 조작 가능한 것의 테두리 — 3:1 필요 (§3) */
  --el-border-color-light:  var(--rule);   /* 장식 구분선 */
  --el-border-color-lighter: var(--rule);
  --el-bg-color: var(--paper);
  --el-bg-color-page: var(--paper-bg);
  --el-text-color-primary:   var(--ink);
  --el-text-color-regular:   var(--ink);
  --el-text-color-secondary: var(--ink-60);
  --el-font-family: 'Pretendard', system-ui, sans-serif;
}

/* e-Paper에는 그림자가 없다 */
.el-card, .el-dialog, .el-dropdown-menu, .el-popper, .el-message-box {
  box-shadow: none;
  border: 1px solid var(--rule);
}
```

Element Plus의 파랑(`#409EFF`)이 한 군데도 남지 않아야 한다. **빌드 후 `409EFF`로 grep해서
0건인지 확인한다** — 남아 있으면 컨셉이 깨진 것이다.

## 8. 차트 (Chart.js)

**노드가 2개뿐이라 색 없이 구분된다.**

| 차트 | 규칙 |
|---|---|
| 배터리 추이 (라인) | 노드 1 = 실선, 노드 2 = 파선. 둘 다 `--ink` 1.5px. 점 없음 |
| 성공률 (도넛) | 성공 = `--ink`, 실패 = `--epd-red`. 2조각. 가운데에 픽셀 폰트 수치 |
| 종이 절감 (누적) | 차트 없이 **큰 픽셀 숫자 하나**. 차트로 만들 값이 아니다 |

격자선 1px `--rule`, 축 라벨 Pretendard 12px `--ink-60`, 수치 라벨 Neo둥근모 16px.
그라데이션·채움·그림자 금지. 범례는 색 견본이 아니라 **선 스타일 견본**(실선/파선)으로 그린다.

노드가 3개 이상으로 늘면 점선·일점쇄선을 추가한다. **색을 추가하지 않는다.**


배포가 진행 중이면 미리보기 위에 **진행 상태가 겹쳐진다**(`SET_FIELD 3/4` 같은 단계 표시).
배포가 끝나면 미리보기 내용이 **즉시 바뀐다** — 페이드 없이. 이게 시연의 하이라이트다.

가로가 1280px 미만이면 미리보기를 ×1(296×128)로 내린다. **정수 배율만 쓴다.**

### 9.2 게시물 관리

좌: 템플릿 선택 → 동적 필드 폼. 우: **라이브 미리보기**(입력할 때마다 즉시 갱신).
필드가 픽셀 폭을 넘으면 §6.4대로 경고.

### 9.3 배포

노드별 진행을 **단계로** 보여준다 — `SET_TEMPLATE → SET_FIELD ×n → SET_QR → COMMIT`.
재전송이 일어나면 그 단계에 `--epd-red`로 재시도 횟수를 붙인다. 실패는 `✕` + 빨강 + "실패".

### 9.4 통계

§8의 규칙대로. 화면 위쪽에 종이 절감 누적 수치를 픽셀 64px로.

### 9.5 시뮬 패널 — 숨기지 않는다

손실률 슬라이더와 노드 전원 토글은 **시연 중 일부러 장애를 일으키는 장치**다.
심사위원 앞에서 노드를 꺼서 오프라인 판정과 재전송을 실시간으로 보여줄 수 있다.
사이드바 구석이 아니라 대시보드 하단에서 바로 닿게 둔다. 가상 모드일 때만 노출.

## 10. 접근성

색을 하나만 쓰는 디자인은 접근성이 쉽게 깨진다. 아래는 타협하지 않는다.

- **색만으로 상태를 표현하지 않는다** — 경고는 항상 형태 + 텍스트를 동반한다 (§3 표).
  빨강을 못 보는 사람도 `○`와 "오프라인"을 읽는다.
- **`--ink-40`(3.45:1)은 텍스트에 쓰지 않는다.** 테두리 전용.
- **`--rule`(1.49:1)은 조작 가능한 요소의 테두리에 쓰지 않는다.** 장식선 전용 (§3).
- 포커스 링은 2px `--ink` 실선. `outline: none` 금지 — 그림자를 없앤 디자인이라 포커스가
  더더욱 테두리로만 드러난다.
- 미리보기 캔버스는 그림이라 스크린리더가 못 읽는다. `aria-label`로 현재 표시 내용
  (템플릿명 + 필드 텍스트 + QR URL)을 문장으로 제공한다.

## 11. 개방점

- **Pretendard vs 시스템 폰트** — Pretendard(약 1.5MB, 서브셋 시 훨씬 작음)를 번들할지, 시스템 한글 폰트로
  갈지. 자체 호스팅 원칙상 번들이 맞지만 용량은 측정 후 판단.
- **e-Paper 적색을 실제로 쓸 패널이 없다** — 현재 하드웨어는 흑백 2색(GxEPD2_290_T94)이다.
  `--epd-red`는 **대시보드 전용 은유**이지 노드가 실제로 빨강을 그리지는 않는다. 심사위원이 물으면
  솔직히 답한다. 3색 패널로 바꾸면 미리보기에도 적색이 들어온다(스트레치).
- 다크 모드 — 하지 않는다. 종이는 어두워지지 않는다.
