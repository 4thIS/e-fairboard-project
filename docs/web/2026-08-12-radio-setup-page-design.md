# 무선 셋업 페이지 — PC HAT 주파수 설정 도구 (브링업 편의) (v1.0)

> 2026-08-12 · 담당: 우진(`wj`) · 대상: `server/backend/app/radio/`, `server/backend/app/routers/`, `server/frontend/`
> 선행: [PROTOCOL.md](../PROTOCOL.md) v0.2, [2026-07-14-dashboard-design.md](2026-07-14-dashboard-design.md)
> 성격: **브링업(하드웨어 준비) 편의 도구.** 운영용 상시 기능이 아니다. PC HAT 전용.

## 1. 목적·범위

LoRa HAT(EBYTE E22-900T22S)의 **주파수(채널)를 웹에서 설정**한다. 지금은 CLI 스크립트로만 가능한
`C0`/`C1` 레지스터 설정을, 브링업 중 편하게 쓰도록 웹 페이지로 옮긴다.

**범위:** PC에 USB로 물린 HAT의 **주파수만** 설정. 포트 자동 목록. 설정 모드 감지·안내.
**범위 밖:** 노드 HAT 설정(원격 불가), 공중속도·출력·주소 등 다른 레지스터, 서버측 값 영속화(HAT
자체 플래시가 저장), M1 소프트 제어(하드웨어상 점퍼라 불가).

## 2. 배경 — 왜 "주파수만", 왜 "브링업 도구"

2026-08-12 실물 브링업에서 확인한 사실:

- 모듈 = **EBYTE E22-900T22S**(SX1262, 900MHz대 850~930), Waveshare SX126X LoRa HAT, CP2102 → COM 포트.
- **설정 모드 = M1 점퍼 빼기(HIGH), M0 꽂기(LOW).** 이 모드에서만 `C1`(읽기)/`C0`(쓰기)에 응답.
  UART는 설정 모드에서 9600 고정.
- 레지스터 `C1 00 09` → `00 00 00 62 E0 <ch> 43 00 00`. 채널 바이트만 주파수를 정함: `freq = 850 + ch`.
  공장기본 ch=18 → 868MHz(EU). KR920은 ch≈72 → 922MHz.
- **주파수 외 나머지(주소0·NET0·UART9600·공중2400·240B·22dBm)는 이미 v0.2 기준과 일치** → 바꿀 게 주파수뿐.

왜 상시 대시보드 컨트롤이 아니라 별도 브링업 도구인가:

- **채널은 시스템 전역·배포 고정값**이다. PC와 모든 노드가 같은 채널이어야 통신되고, 바꾸는 순간
  기존 노드와 두절된다. 매일 만지는 값이 아니다.
- PC HAT은 **설정 모드 진입에 물리 점퍼(M1)**가 필요해 "완전 웹만으로"는 불가 — 페이지가 안내한다.
- 무선 파라미터 값 자체는 준표(프로토콜 주관)가 정한다. 이 도구는 **값을 적용**할 뿐 정하지 않는다.

## 3. 아키텍처 (접근 A — 독립 설정 유틸)

서버 최초의 실제 pyserial 코드다. 미구현인 SerialTransport에 묶지 않고 **독립 유틸**로 만든다.
요청마다 포트를 **on-demand로 열고 닫으며**, `Lock`으로 직렬화한다. 가상 모드(포트 비어 있음)에서
그대로 동작한다.

```
[RadioSetupView.vue] ─HTTP─ [FastAPI /api/radio/*] ─pyserial(on-demand)─ [PC HAT] (COM 포트)
```

## 4. 백엔드 (2파일 + 의존성)

### 4.1 `app/radio/e22.py` — 순수 로직 (하드웨어 무관, 테스트 가능)

- `channel_to_mhz(ch) -> int` / `mhz_to_channel(mhz) -> int` : `freq = 850 + ch`.
- `decode_registers(nine_bytes) -> dict` : 주소·NETID·UART·공중속도·채널·주파수·출력·옵션.
- `build_read_cmd() -> bytes` : `C1 00 09`.
- `build_write_cmd(current9: bytes, mhz: int) -> bytes` : 현재 레지스터에서 **채널 바이트만** 교체한
  `C0 00 09 + 9B`. (나머지 레지스터 보존 — 주파수만 바꾼다.)
- 상수: `BASE_MHZ=850`, `HW_MIN=850`, `HW_MAX=930`, `KR920=(920.9, 923.3)`.

### 4.2 `app/routers/radio.py` — 엔드포인트 3개 (전부 `require_token`)

| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | `/api/radio/ports` | 사용 가능 COM 포트 `[{device, description}]` (pyserial `list_ports`) |
| POST | `/api/radio/read` | `{port}` → 포트 열어 `C1 00 09` → 디코드값. 무응답이면 `{ok:false, hint}` |
| POST | `/api/radio/frequency` | `{port, mhz}` → 읽기(설정모드 확인) → 채널만 쓰기 → 재읽기 검증 → `{ok, before, after}` |

- 포트 **매 요청 open→close**, 모듈 전역 `Lock`으로 직렬화(동시 open 방지).
- `mhz` 검증: `HW_MIN~HW_MAX`(850~930) 밖이면 **422 거부**. KR920 밖이면 응답에 `warn` 플래그(허용).
- `read`가 설정 모드 감지기 역할: 응답 없으면 `hint="설정 모드 아님 — M1 점퍼를 빼세요"`.

### 4.3 의존성

- `pyserial`을 `requirements.txt`에 추가(현재 없음). 실모드 전송에도 어차피 필요하다.

## 5. 프론트엔드

- **새 라우트 `/setup/radio`** (로그인 가드). 대시보드에 작은 "무선 설정" 진입 링크. 운영 화면과 분리.
- **`RadioSetupView.vue`** (다크 관제센터 토큰 재사용):
  1. **포트 드롭다운** — `GET /ports` 로드 + 새로고침 버튼, description(CP2102 등) 표시.
  2. **[현재 설정 읽기]** — `POST /read` → 주파수·공중속도·출력 디코드 카드. 실패 시 **"M1 점퍼를
     빼서 설정 모드로" 안내 박스**.
  3. **목표 주파수 입력**(MHz, 예 922) → **[설정 쓰기]** → `POST /frequency` → **before→after + 검증**.
- **상시 안내 배너**: `M1 빼기(설정) → 쓰기 → M1 다시 꽂기(전송)` 3단계 + KR920 범위(920.9~923.3).

## 6. 안전장치 (이 도구의 핵심)

- **쓰기 전 확인 다이얼로그** — "⚠ PC와 **모든 노드가 같은 채널**이어야 통신됩니다. 계속?"
- **설정모드 인터록** — 쓰기 버튼은 **직전 읽기 성공**(=설정 모드 확인) 후에만 활성. 눈먼 쓰기 금지.
- **입력 검증** — 850~930MHz만 허용(하드웨어 범위). KR920 밖이면 노란 경고(브링업이라 허용은 함).
- **되돌리기 용이** — 잘못 써도 다시 쓰면 복구(HAT 레지스터 덮어쓰기).

## 7. 에러 처리

| 상황 | 처리 |
|---|---|
| 포트 열기 실패 | "다른 프로그램이 포트 점유? 포트 확인" (409/503) |
| 읽기 무응답 | "설정 모드 아님 — M1 점퍼 빼고 다시" (hint) |
| 쓰기 검증 불일치 | "쓰기 실패, 재시도" + before/after 표시 |
| mhz 범위 밖 | 422 (프론트 입력 제한 + 백엔드 이중) |
| 401 | 로그인 리다이렉트 |

## 8. 테스트

- **백엔드 단위테스트(`e22.py`)** — 하드웨어 없이: `channel_to_mhz(18)==868`, `mhz_to_channel(922)==72`,
  `decode_registers(bytes.fromhex("000000 62E0 12 43 0000"))` 필드값, `build_write_cmd`가 채널 바이트만
  바꾸고 나머지 보존. 실측 골든벡터(`62 E0 12 43`, ch18=868, ch72=922) 사용.
- **fake-serial 테스트** — read/write 라우터 로직을 바이트 주입 가짜 시리얼로(설정모드 응답/무응답 분기).
- **수동** — 실물 HAT(COM5)로 read→frequency→verify 왕복.

## 9. 범위 밖 (명시)
- 노드 HAT 설정, 공중속도·출력·주소·NETID·암호화 설정, 서버측 채널 영속화, M1 소프트 제어,
  SerialTransport(실모드 배포)와의 통합 — 별개 작업.
