## 1. 배경·범위

기존 구현은 "심사위원 시연"을 1순위로 한 전자 종이 컨셉이었다. 재설계의 전제를 바꾼다 —
**1순위는 실제 관리자 운영 도구**다. 관리자가 화면을 열었을 때 가장 먼저 답해야 할 질문은
**"노드들이 지금 정상인가"**이고, 대시보드는 그 질문의 답 + 즉시 조치(내용 수정·배포)까지를
한 화면에서 끝낸다.

이번 범위: **앱 뼈대(로그인·라우터) + 대시보드 페이지.**
배포 이력·예약·통계·시뮬 패널 등 나머지 페이지는 다음 설계에서 다룬다.

## 2. 확정 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 1순위 관객 | **실제 관리자** (시연은 부차) | 사용자 결정 |
| 화면 주인공 | **노드 상태** — 노드 카드 2장이 화면 전체 | "지금 정상인가"가 첫 질문 |
| 수정·등록 흐름 | **노드 중심(A안)** — 카드 [내용 수정] → 다이얼로그(현재 내용 채워짐) → 저장=이 노드에 배포 | 클릭 두 번으로 조치 완료 |
| 공유 게시물 수정 | **게시물 직접 수정 + 이 노드만 재배포.** 같은 게시물을 쓰는 다른 노드는 옛 화면 유지 | 미리보기는 `display_state`(실제 커밋 화면) 기준이라 거짓말하지 않음. 구현 최소 |
| 비주얼 | **다크 관제센터(B안)** — 어두운 배경, e-Paper 미리보기가 발광하듯 도드라짐, 상태색 초록/빨강/호박 | 모니터링 툴 문법, 주인공 질문과 일치 |

| 폰트 | UI = 시스템 폰트 스택(모노 위주). **미리보기 내부만 Neo둥근모 자체 호스팅** | 미리보기·노드 픽셀 동일 원칙, 시연장 인터넷 없음 |

## 3. 레이아웃 — 세 가지 상태

목업: `.superpowers/brainstorm/1406-1784039908/content/dashboard-layout.html` (git 미추적, 참고용)

### 3.1 평상시

```
┌ E-FAIRBOARD          ● 게이트웨이 연결됨 [가상 모드] 온라인 1/2 ┐
│  ┏━━━━━━━━━━━━━━━┓   ┏━━━━━━━━━━━━━━━┓ (빨간 테두리)      │
│  ┃ e-Paper 미리보기 ┃   ┃ 어두운 미리보기   ┃                  │
│  ┃ (발광, ×2 배율)  ┃   ┃ "마지막 커밋 화면" ┃                  │
│  ┗━━━━━━━━━━━━━━━┛   ┗━━━━━━━━━━━━━━━┛                  │
│  NODE 0x01 ● ONLINE     NODE 0x02 ○ OFFLINE               │
│  BATT 3.9V 82% · RSSI -62 · 3초 전    마지막 응답 5분 전     │
│  게시물: 행사 안내 #12               게시물: 부스 지도 #8      │
│  [내용 수정] [PING] [이력]           [내용 수정(비활성)] …    │
└──────────────────────────────────────────────────────────┘
```

- 오프라인 카드: 빨간 테두리, 미리보기 어둡게 + "마지막 커밋 화면" 라벨 (e-Paper는 전원이
  없어도 마지막 화면을 유지하므로 이것이 물리적 사실이다), [내용 수정] 비활성.
- 상단 바: 게이트웨이 연결 상태(가상 모드 배지 포함), 온라인 노드 수, 로그아웃.

### 3.2 배포 진행 중 — 카드가 진행판이 된다

- 카드 테두리 호박색, 미리보기 위 반투명 오버레이에 단계 목록:
  `✓ SET_TEMPLATE / ✓ SET_FIELD 1/3·2/3 / ▶ SET_FIELD 3/3 (재시도 2) / · SET_QR / · COMMIT`
- 하단에 진행 바. COMMIT 성공 순간 오버레이가 걷히고 미리보기가 새 내용으로 즉시 교체.
- 실패 시: 카드 빨간 테두리, `✕ 실패 — SET_FIELD 3/3에서 중단` + [재시도] 버튼.

### 3.3 편집 다이얼로그

- 좌: 템플릿 셀렉트 + 동적 필드 폼 + QR URL. 현재 게시물 내용이 미리 채워진 채 열림.
  다른 게시물로 바꾸기·[+ 새로 만들기]는 상단 게시물 드롭다운에서.
- 우: 라이브 미리보기(입력마다 즉시 갱신) + 갱신 방식(◉ 부분 / ○ 전체).
- 픽셀 폭 초과 필드: 입력창 빨간 테두리 + "⚠ 화면에서 잘립니다". **경고만, 저장 차단 없음**
  (차단은 max_bytes 초과만 — b652142에서 확정한 issue-kind 규칙 유지).
- 푸터: [취소] [저장하고 이 노드에 배포].

## 6. 데이터 흐름

### 6.1 조회

- 진입 시: `GET /api/nodes` + `GET /api/templates` + `GET /api/posts` (현재 게시물 제목 표시용)
- `nodes` 5초 폴링. 노드 상세의 `display_state`(커밋된 template_id·fields·qr_url)가
  카드 미리보기의 데이터 소스 — **입력값이 아니라 실제 커밋 화면**을 그린다.

### 6.2 저장=배포

1. 기존 게시물 수정 → `PUT /api/posts/{id}` / 새로 만들기 → `POST /api/posts`
2. `POST /api/deployments {post_id, node_ids: [이 노드], refresh_mode}` → `deployment_id`
3. 카드가 배포 진행 상태로 전환, `GET /api/deployments/{id}` 1초 폴링
4. 완료(success) → `GET /api/nodes` 즉시 재조회 → 미리보기 교체 / 실패 → §3.2 실패 상태

### 6.3 백엔드 확장 — DeployTarget 단계 필드 (이번 작업에 포함)

단계 표시(`SET_FIELD 2/3`, 재시도)를 위해 `DeployTarget`에 필드 3개를 추가한다:

```python
step_name: str = ""     # "SET_TEMPLATE" | "SET_FIELD" | "SET_QR" | "COMMIT"
step_index: int = 0     # 현재 단계 (1-base). SET_FIELD는 필드마다 증가
step_total: int = 0     # 전체 단계 수 (템플릿 필드 수에 따라 가변)
```

- `deploy_service`가 각 패킷 전송 직전에 갱신. `attempts`는 기존 필드 그대로 재시도 표시에 사용.
- 기본값이 있어 기존 JSON 스냅샷과 호환. API 응답(`GET /deployments/{id}`)에 자동 포함.
- 백엔드도 우진 영역이므로 협의 불요. 프로토콜·패킷 계층은 건드리지 않는다.

## 7. 에러 처리

| 상황 | 처리 |
|------|------|
| 노드 오프라인 | [내용 수정] 비활성 + PING 버튼으로 재확인 유도 |
| 배포 실패 | 카드 빨간 테두리 + 실패 단계 표시, [재시도] = 같은 post·node로 새 deployment |
| 픽셀 폭 초과 | 경고만 (저장·배포 가능) — 노드가 잘라내는 것과 동일한 결과를 미리보기가 보여줌 |
| max_bytes 초과 | 프론트 입력 차단(UTF-8 바이트 계산) + 백엔드 422 이중 검증 |
| 401 | axios 인터셉터 → 로그인 리다이렉트 |
| 게이트웨이 단절(실모드) | 상단 바 `● 연결 끊김`(빨강) — 표시만, 재연결은 백엔드 책임 |

## 9. 참고 — LoRa 레퍼런스 저장소와의 관계

사용자 공유 레퍼런스(https://github.com/ssenu/esp32_e-paper_syllabus)는 실사용 예정 모듈과
같은 계열(EBYTE LoRa HAT, 투명 UART 9600bps)의 통신 구현이다. 핵심: **HAT를 서버 PC에 직결**
(별도 게이트웨이 없음), 단일 전송 ≈ 29B → BEGIN/DATA 청크 + stop-and-wait ACK(txn),
e-Paper 렌더 중 수신 불가를 재전송으로 흡수.

- 이는 PROTOCOL.md v0.1의 전제(Core1262 SPI + ESP32 게이트웨이 + COBS + 200B 페이로드)와
  충돌한다. **프로토콜 스펙 주관은 준표 — 팀 협의 필요.** 백엔드 transport 계층 개편은
  협의 후 별도 작업으로 다룬다.
- **대시보드는 영향 없음**: REST API가 절연층이다. 다만 "전송이 느리고 재시도가 잦다"는
  현실이 확인되어 §3.2 단계·재시도 표시의 가치가 높다.
