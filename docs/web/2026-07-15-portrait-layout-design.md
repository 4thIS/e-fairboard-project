# 세로(portrait) 레이아웃 + 팀 소개 팜플렛 (v1.0)

> 2026-07-15 · 담당: 우진(`wj`) · 대상: `server/backend/app/protocol/templates.py`, `server/frontend/`
> 선행 문서: [2026-07-14-dashboard-design.md](2026-07-14-dashboard-design.md)(대시보드), [2026-07-08-web-design.md](2026-07-08-web-design.md)(백엔드 구조)
> **⚠ 이 스펙은 웹만으로 완결되지 않는다.** 실제 하드웨어에 세로로 그리려면 노드 펌웨어 변경이 필요하다(§6, 준표 협의).

## 1. 목적

지금 템플릿은 전부 가로(296×128)다. e-Paper 패널을 **물리적으로 세워** 128×296으로 쓰는
세로 레이아웃을 지원하고, 그 위에 **경진대회 팀 소개 팜플렛** 템플릿을 하나 얹는다.

## 2. 확정 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 방향의 주인 | **템플릿의 속성** | SET_TEMPLATE 에 `template_id` 가 이미 실려 가므로 **프로토콜 변경이 없다**. 노드는 템플릿을 보고 캔버스를 안다 |
| 세로 템플릿 개수 | **1개** (id=4 "팀 소개") | 방향 지원의 배관을 뚫는 게 목적. 더 필요하면 좌표만 추가 (YAGNI) |
| 소개 문장 | **화면엔 팀명·주제만, 상세 소개는 QR 너머로** | 폭 120px = 한글 7자. 문단을 욱여넣지 않는다. QR이 실제 쓸모를 얻는다 |
| 글자 크기 | **전부 16px** (32px 안 씀) | 32px 한글은 폭 120px 안에 **3자**밖에 못 들어간다 — 한글 팀명이 잘린다 |
| 더 작은 폰트 | **하지 않는다** | 16px 은 우리가 고른 값이 아니라 `efb_hangul16`(16×16 비트맵)이 강제하는 바닥. 12px 로 갈아도 한 줄 10자라 **"소개는 QR 너머로"라는 결론이 바뀌지 않는다**. 폰트 교체 비용(펌웨어 `GLYPH_CELL`·좌표·테스트 벡터 전면 재작성)만 크다 |
| 미리보기 배율 | `높이×2 ≤ 320` 이면 ×2, 아니면 ×1 | 정수 배율 원칙 유지. 가로=×2(256px), 세로=×1(296px) 로 두 카드가 나란히 균형 |

### 왜 폰트를 갈지 않는가 (기록)

"글씨를 더 작게" 요청에 대한 조사 결과다. 노드 폰트는 한글 글리프를 **16×16 비트맵**으로 굽고
(`tools/gen_font.py` → `efb_hangul16.bin`), 렌더러는 **정수 배율만** 한다(`scale_for`: 16→×1, 32→×2).
16px 미만은 배율 0 = 글자 소멸이라 `scale_for` 가 최소 ×1 로 막고 있다. 더 작게 하려면 폰트 자체를
갈아야 한다(갈무리11·갈무리9 등, OFL이라 라이선스는 무관).

물리 크기: 2.9" 패널을 세우면 **가로 29mm** → 16px 한글 ≈ 3.6mm / 12px ≈ 2.7mm / 9px ≈ 2.0mm
(신문 본문 2~3mm). 12px 는 손에 들면 읽히나 벽에 걸면 흐리고, 9px 는 획이 뭉개져 복잡한 음절이 깨진다.

**결론: 갈아도 문제가 안 풀린다.** 12px 로 가도 한 줄 10자 — 제대로 된 소개(40자+)는 여전히 안 들어간다.
문장을 화면에 담으려면 폰트가 아니라 **패널을 키워야** 한다(4.2" 400×300 → 세로 폭 300px = 한글 18자/줄).
그건 하드웨어 변경이므로 이 스펙 밖이다.

## 3. 캔버스를 템플릿의 속성으로

현재 `CANVAS_W=296` / `CANVAS_H=128` 은 `templates.py` 의 **모듈 전역 상수**이고,
`field_avail_w()` 가 이를 직접 참조한다:

```python
right = qr.x if overlaps else CANVAS_W   # ← 296 하드코딩
```

세로 템플릿(폭 128)에서 이 값을 그대로 쓰면 **가용 폭이 2배 넘게 틀린다** — 노드는 128px 에서
잘라내는데 서버·미리보기는 296px 까지 쓸 수 있다고 말한다. 미리보기가 거짓말을 한다.

**그래서 캔버스를 `TemplateDef` 로 내린다.**

```python
@dataclass(frozen=True)
class TemplateDef:
    id: int
    name: str
    fields: tuple[FieldDef, ...]
    qr: QrDef
    canvas_w: int = 296   # 기존 4개 템플릿은 기본값으로 그대로 (가로)
    canvas_h: int = 128

def field_avail_w(f: FieldDef, qr: QrDef, canvas_w: int) -> int:
    ...
    right = qr.x if overlaps else canvas_w
```

기존 호출부(`as_dict`, `test_max_bytes_fits_screen_width`)가 캔버스를 넘기도록 바뀐다.
기본값이 있어 기존 템플릿 정의는 한 글자도 안 바뀐다.

## 4. 새 템플릿 (id=4 "팀 소개")

캔버스 **128×296**. 전부 16px, 여백 x=8 → 가용 폭 **120px**(한글 7자 / ASCII 15자).
노드 렌더러는 **텍스트와 QR만** 그린다 — 선·도형·배경이 없으므로 구분선은 두지 않는다.
필드 4개로 노드의 `TEMPLATE_MAX_FIELDS = 4` 한도에 정확히 맞는다(헤더 구조 변경 불필요).

| field_id | 이름 | x | y | font_size | max_bytes | avail_w |
|:---:|---|---:|---:|:---:|---:|---:|
| 0 | 팀명 | 8 | 8 | 16 | 21 | 120 |
| 1 | 주제1 | 8 | 40 | 16 | 21 | 120 |
| 2 | 주제2 | 8 | 62 | 16 | 21 | 120 |
| 3 | 주제3 | 8 | 84 | 16 | 21 | 120 |

QR: `QrDef(x=16, y=140, size=96)` — 가로 가운데 정렬((128-96)/2 = 16). 세로로 140+96 = 236 ≤ 296.

- **QR과 세로로 겹치는 필드가 없다**(최하단 필드는 y=84~99, QR은 y=140~235) → 모든 행의 `avail_w` 가 120px.
- `max_bytes = 21` — 한글 7자 = 21B. `field_avail_w` 가 계산한 120px 와 일관된다.
  (ASCII 가 섞이면 바이트는 남는데 픽셀이 남을 수 있으나, 그건 기존 픽셀 폭 경고가 잡는다.)

## 5. 프론트엔드

- `epaper/types.ts`: 전역 `CANVAS_W`/`CANVAS_H` 상수를 제거하고 `TemplateDef` 에 `canvas: {w, h}` 를 받는다.
  (지금 두 상수를 쓰는 곳은 `EpaperPreview.vue` 뿐이다.)
- `EpaperPreview.vue`: 캔버스 크기를 props 의 템플릿에서 읽는다. 템플릿이 없으면(미배포 노드)
  가로 296×128 로 그린다 — 빈 화면의 기본 모양.
- **배율 규칙**: `scale = (canvas_h * 2 <= 320) ? 2 : 1`. `NodeCard` 의 기존 뷰포트 규칙
  (1280px 미만 → ×1)과 곱해서 최종 배율을 정한다. 정수 배율만 나온다.
- `NodeCard`: 가로·세로 카드가 섞여도 무너지지 않도록 미리보기 영역을 `align-items: flex-start` 로.
- `EditDialog`: 템플릿 셀렉트에 "팀 소개"가 자동으로 뜬다(템플릿 목록을 API에서 받으므로 코드 변경 없음).
  라이브 미리보기도 세로로 그려진다.

## 6. ⚠ 펌웨어 협의 항목 (준표) — 이 스펙 범위 밖

웹만으로는 **실제 노드에 세로로 그릴 수 없다.** 노드 쪽에 다음이 필요하다:

1. `node/lib/node_core/include/node/templates.h` — `TemplateDef` 에 `canvas_w`/`canvas_h` 추가
   (이 헤더는 `tools/gen_templates.py` 가 `templates.py` 에서 **자동 생성**하므로, 생성기를 고치면 따라온다).
2. `node/lib/node_core/src/layout.cpp` — `field_avail_w()` 가 전역 `CANVAS_W` 대신 **템플릿의 캔버스 폭**을 쓰도록.
   현재 서버와 같은 식이므로 한쪽만 고치면 `tools/check_drift.py` 가 잡는다.
3. `node/src/main.cpp` — 세로 템플릿이면 `display.setRotation()` 으로 패널을 90° 돌려 그린다.
4. **하드웨어**: 해당 노드를 물리적으로 세워서 설치(효민).

**웹은 이것들과 독립적으로 완결된다** — 가상 노드는 필드를 저장만 하고 렌더하지 않으므로,
시뮬레이터 E2E·대시보드 미리보기·편집 다이얼로그는 오늘 바로 동작한다.
펌웨어를 기다리는 것은 "실제 패널에 세로로 그리는 것" 하나뿐이다.

## 7. 테스트

- `field_avail_w` 가 **템플릿 캔버스를 쓰는지**: 세로 템플릿(폭 128)에서 296이 아니라 120이 나오는지.
- 기존 `test_max_bytes_fits_screen_width` 가 새 템플릿에도 적용되는지 — `max_bytes` 가 `avail_w` 안에 들어가는지
  (템플릿 4개 → 5개로 자동 확장되므로 회귀 테스트가 새 템플릿을 자동으로 검증한다).
- 프론트 `text.spec.ts` 에 세로 폭(120px) 잘라내기 케이스 추가 — 노드와 같은 규칙인지.
- `GET /api/templates` 응답에 `canvas` 가 실리는지 (API 테스트).

## 8. 범위 밖

- 세로 템플릿 추가 생성(행사 안내 세로판 등) — 좌표만 추가하면 되므로 필요할 때.
- 폰트 교체(12px/9px) — §2 참조. 하지 않는다.
- 자동 줄바꿈 렌더러 — 노드 `draw_utf8` 은 한 줄만 그리고 잘라낸다. 바꾸지 않는다.
- 노드별 방향 등록·검증 — 방향은 템플릿의 속성이고, 미리보기가 세로로 보이므로 잘못 고르면 바로 보인다.
